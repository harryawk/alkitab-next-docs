# Full functional parity with upstream develop

The goal is parity with `yukuku/androidbible` on its `develop` branch across iOS, Android and web, meaning the same user-visible behavior and the same data formats, not the same code or pixels. Upstream moves, so each row of the parity matrix records the upstream commit it was verified against and a scheduled job reports upstream commits touching ported areas. Android-only features (widget, push, audio, volume-key paging) get the nearest equivalent on each platform; online features are parked in one ticket until the maintainer's terms for `api.alkitab.app` are confirmed. Upstream's own survey estimates ~1,850 engineer-hours for a native iOS port, so scope is large by design and phased: yes-parser tickets, then user data, then search, then the rest.

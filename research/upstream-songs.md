# Upstream song content: bundled or fetched, and its license

Issue: #33 (Songs). Upstream: `yukuku/androidbible`, branch `develop`, HEAD `583d7fbd82d302fb3993c5c8e67421b1cd271b16` (committed 2026-10-16T02:22:55Z), read through `gh api` on 2026-10-18.

Source tags used below:
- [API] read with `gh api` against `yukuku/androidbible` at `develop`.
- [INFERRED] a conclusion drawn from the cited sources, not stated in them.

## Decision

Song content is fetched from the upstream server at runtime. Nothing in the app bundle is a song book. The ticket's move-to-Online-features path applies. The bundled path does not apply, and the song content has no license that clearly allows shipping it, so it could not be bundled on this evidence even if it were in the APK.

## Where song content lives

1. Song books come from the server. [API] `Alkitab/src/main/java/yuku/alkitab/songs/SongBookUtil.kt` line 171 downloads a book from `BuildConfig.SERVER_HOST + "/addon/songs/get_songs?name=...&dataFormatVersion=..."`. [API] `SongViewActivity.kt` line 288 links to `${BuildConfig.SERVER_HOST}/songs/downloads?dataFormatVersion=...` to list downloadable books. [API] `SongViewActivity.kt` lines 372 and 382 fetch song audio from `${BuildConfig.SERVER_HOST}/addon/audio/...`.
2. The server answers `get_songs` with a 302 redirect to a static artifact. [API] `docs/features/portable-songs/design.md` section 7 says the redirect goes to `.../songs/v1/data/<book>-5.json.gz` for new clients, and to `<book>-4.ser.gz` for old clients. Static artifacts are published to `boafiles.kejut.com`. [API] same file, section 7.
3. The song corpus is generated by a separate repo, `yukuku/kidung-data`. [API] `docs/features/portable-songs/design.md` section 7 names it. [API] `docs/developer/songs.md` links to `kidung-data/docs/newdoc/20260615-newdoc-format.md`. `gh api repos/yukuku/kidung-data` returned 404 for this account, so its contents, license and size are unconfirmed [API, unconfirmed].
4. The app ships no song book data. [API] A recursive tree listing of `develop` (2164 entries, not truncated) has no song book file in any `src/*/assets` directory. The only song-related assets are the templates `templates/song.html` and `templates/song.css`, plus `docs/` files.
5. The `ddd_k01.txt` to `ddd_k66.txt` files under `Alkitab/src/plain/assets/internal/` are not songs. [API] `docs/binary-formats.md` says they are the dummy Bible text ("Dummy Debug Data") for the open-source `plain` build, with prefix `ddd`. Do not read them as song content.
6. The test fixture `Alkitab/src/test/resources/songs/kri25-doc.json` (994 bytes) and `Alkitab/src/test/resources/fixtures/download_all.json` (833147 bytes) are test data [API]. The first is one song document. The second starts with a `snapshots.pins` key and is not song data [API, from the first 300 bytes only; the fetch of the full file failed twice, so its full contents are not confirmed].

## Format

- Wire format: gzipped JSON wrapper `{ dataFormatVersion, songs }`, `dataFormatVersion` 5. [API] `docs/features/portable-songs/design.md` section 3.7, and `SongBookUtil.kt` line 142.
- Legacy format: gzipped Java-serialized `List<Song>` (`-4.ser.gz`). [API] `design.md` sections 1 and 7.
- Authoring format: plain-text `.txt` (UTF-8, LF) with metadata lines and `*1`, `*ref`, `===` markers, or the richer `@doc` format. [API] `docs/developer/songs.md`.
- On device: Room table `song_info`, JSON `SongDocument` payload, `dataFormatVersion` 5. [API] `docs/modules/songs.md`, Storage section.

## Size

- Per book: not confirmed. The server-side artifacts were not reachable. The download is capped at 50 MB. [API] `docs/modules/songs.md`, Storage section.
- Corpus total: not confirmed. [API, unconfirmed]

## License

- Project code: Apache License 2.0. [API] `LICENSE.txt` (11358 bytes) and the README "License" section, which reads "Copyright 2009-present The Alkitab App Authors."
- Song content: no license file covers it. No `LICENSE`, `NOTICE` or `COPYING` file in `develop` covers song books [API, tree listing]. The Apache license covers code, not lyrics or music.
- Rights notes that exist:
  - [API] `docs/developer/songs.md`: a song book needs "distribution permission information" and the team "reviews submissions for inclusion in the app." Submissions go to help@alkitab.app.
  - [API] `publication/market_desc.txt`: "Lyrics from various song books or hymnals are available for download." It says the Play listing offers download, not that the content is licensed.
  - [API] `publication/market_desc.txt` also says that some translations were removed "because of copyright issues."
  - [API] `README.md` line 62: "Create and make publicly available your favorite Song Book."
- Conclusion: the license of each song book is set by its contributor and is not stated in this repo. The app does not hold a general license for the song content. [INFERRED from the points above]
